# 云端部署和维护手册

状态：部署材料已准备。没有配置云账号、域名或实际对外发布；必须完成本文件的云端验收后再邀请真实商户。

## 环境边界

- 汇报版 `D:\云迹科技` 和商业版 `D:\云迹科技-商业化` 完全独立。只在后者运行下述命令。
- 开发前端 5174，API 4100；Windows 启动器只管理本目录的两个进程，不停止其他端口进程。
- 本机 `.local/database` 是独立 PGlite 数据库；服务器正式部署要求 PostgreSQL，不能复制浏览器 localStorage 当作数据库。
- 经营 JSON 备份只包含单个空间的业务记录。它不包含账号、密码、会话和系统配置，不能代替整库灾难恢复备份。

## 部署方式

1. 在代码托管或 CI 中检出 `feat/commercial-pilot`，安装 Node 24、pnpm 11.25.0，执行 `pnpm install --frozen-lockfile`、`pnpm run check`、`pnpm run test:e2e`。
2. 在云平台新建 PostgreSQL 数据库，使用专用数据库账号，确认数据库的网络访问范围。当前应用在启动时执行迁移，因此此账号需要本库建表权限。生产权限拆分在上线复核中执行。
3. 构建本仓库 Dockerfile，或安装依赖、执行 `pnpm run build` 后运行 `pnpm start`。不要把 `.env`、数据库目录、备份打进镜像。
4. 通过云平台密钥设置配置以下变量，不能提交 Git：

| 变量 | 说明 |
| --- | --- |
| `NODE_ENV` | `production` |
| `DATABASE_URL` | 本应用的 PostgreSQL 连接串，按数据库供应商要求配置 TLS |
| `APP_ORIGIN` | 唯一的正式 HTTPS 来源，例如 `https://app.example.com`，末尾不加 `/` |
| `INVITE_CODE` | 随机生成、至少 16 字符，只交给受邀试用者 |
| `HOST` | 容器或反向代理环境使用 `0.0.0.0` |
| `PORT` | 默认 `4100`，按云平台配置 |
| `TRUST_PROXY` | 仅应用确实位于一个可信代理后时设为 `1`；此时不能直接暴露应用端口 |

5. 由云平台或反向代理提供 HTTPS。前端静态文件与 `/api` 保持同一域名，生产服务已包含 `dist` 静态服务。
6. 配置外部存活检查访问 `/api/health`、错误日志收集、费用告警和数据库备份。告警要送达实际负责的人。

生产缺少 HTTPS 来源、邀请口令或 PostgreSQL 时会拒绝启动。本机 .env 默认用于开发，不应复制为生产配置。

## 上线验收

- 在两台设备验证同账号数据，在两个账号间验证隔离。
- 确认 HTTPS 与安全 Cookie；在代理后确认登录限流仍按正确来源工作。
- 用测试数据完成客户 → 订单 → 分次收款 → 退款 → 报表，以及商品期初 → 出库 → 预警。
- 在实际 PostgreSQL 上执行 API 验收和迁移演练，验证重启后数据仍在。
- 用户忘记密码的恢复渠道、邮件验证和真正的邀请管理尚需接入并验证，不应开放无限制注册。
- 定时备份、恢复、上一版本回退和错误告警都要实际演练；仅有配置文件不能算通过。

## 备份与恢复

1. 在数据库服务商控制台启用自动备份及适合预算的时间点恢复，明确最多能接受丢失多久数据、多久恢复服务。
2. 定期用官方 PostgreSQL 工具 `pg_dump` 制作独立备份。凭据使用服务商密钥/受保护环境变量，不写进命令历史。
3. 用 `pg_restore` 恢复到全新的测试数据库，核对账户、空间、客户、订单、资金流水、库存流水和审计数量，以及收款净额和库存余额。
4. 恢复演练不能覆盖运行中的数据库。确认完整后，发生真正故障时才按事先审批的恢复流程切换连接。
5. 商户也可从页面导出 JSON，并恢复到新的空工作空间。现有有数据空间不会被覆盖。

官方参考：[PostgreSQL 备份](https://www.postgresql.org/docs/17/backup.html)、[Express 生产安全](https://expressjs.com/en/advanced/best-practice-security/)、[PGlite 本地存储](https://pglite.dev/docs/filesystems)。

## 发布与回退

- 每次发布记录 Git 提交、镜像版本、迁移版本及验收结果。
- 先在测试数据库验证迁移，生产发布前确认可用备份。
- 新增数据库字段优先采用向后兼容方式。只有确认新数据库结构兼容旧应用，才直接回退应用镜像；否则使用独立恢复流程。
- 不运行汇报版的同步脚本。商业版同名同步脚本已禁用。
