# 云迹科技商业化基础版 · 实施计划

计划基准：2026-10-03。实际进度以 [COMMERCIAL_PROGRESS.md](../COMMERCIAL_PROGRESS.md) 的已执行记录为准；本文定义范围和验收条件，不代表功能已经完成，不承诺工期。

## 1. 已确定的边界

- 用户同时经营服务和实物商品，先提供通用基础版。
- 汇报版 `D:\云迹科技` 与基线 `477c672` 保留；商业开发只在 `D:\云迹科技-商业化`、`feat/commercial-pilot` 分支推进。
- 商业版使用前端 5174、API 4100 和独立数据库。不得修改、重置或停止汇报版，不读取其浏览器业务数据作为默认导入。
- 每家工作空间先有一位 owner；客户、订单、商品、收支均归属工作空间。成员邀请、多角色审批暂不作为本阶段交付条件。
- 先用 CNY、手工登记客户回款、独立库存出入库。商品和服务订单共用基础管理能力；服务业务不扣库存，商品库存不自动随订单变化，界面应明确说明。
- AI 先提供读取本空间数据的规则查询与总结。真实 LLM 是可选扩展，不能代替账务计算或直接修改经营记录。
- 平台向经营者收取的订阅费，与经营者登记的客户订单回款分别建模、分别展示，不能混入同一经营账本。

接口、并发和流水规则详见 [API_CONTRACT.md](API_CONTRACT.md)。需用户提供的账户与业务决定详见 [USER_ACTIONS.md](USER_ACTIONS.md)。

## 2. 当前实现状态

截至本文建立时，S0 独立仓库已创建，S1/S2 正在实现。汇报版原有测试通过记录只证明汇报版可用，不能证明商业版权限、数据库或收费能力已验收。

以下事项在有明确实现和验证证据前，一律视为未完成：真实生产部署、生产 PostgreSQL 验证、跨租户安全验收、云端自动备份及恢复演练、邮件验证与忘记密码恢复、支付开通、真实试用、真实 LLM 接入。

## 3. 阶段 S0–S5

### S0 · 隔离开发与断点保护

交付：独立仓库、分支、端口、数据库目录、配置样例和恢复入口。

最小验收：

- 原汇报仓库、文件、启动脚本、运行进程和浏览器数据保持不变。
- 商业版脚本只操作商业目录及商业进程；复制来的同步脚本不能继续向汇报目录写入。
- `.local/`、数据库、备份、日志、真实环境配置和密钥不进入 Git；可提交不含凭据的配置样例。
- 中断后能从检查点识别当前分支、最后实际通过的验证、未完成工作和下一条操作。

### S1 · 真实身份与工作空间数据

交付：注册/邀请、登录/退出、数据库持久化、服务端业务接口、修改密码和审计基础。

最小验收：

- 登录依赖服务端会话和 HttpOnly Cookie，修改浏览器标记不能获得权限。
- 每个读取、写入、导出、恢复、AI 和审计请求都以会话工作空间限定；不能信任客户端传入的 workspace_id。
- 两个独立账户互相猜测记录 ID、退款原流水 ID、商品 ID，均不能读写对方数据。
- 未登录请求被拒绝；CSRF 缺失/错误、非允许 Origin 的写请求被拒绝。
- 密码不明文保存；改密后旧会话按接口约定失效；错误响应和日志不输出密码、会话值或数据库栈。
- 同一账户在第二个浏览器看到相同服务器记录；服务重启后数据仍在。

本阶段使用 PGlite 支持本地开发。生产 PostgreSQL 的迁移、事务和并发行为仍需在 S3/S4 单独验证。

### S2 · 账务、库存与前端闭环

交付：四模块接入服务端；独立收款/退款流水、库存流水、冲突检测、重复提交保护和统一统计。

最小验收：

- 回款按实际流水日期计算，订单 paidAmount 由净收款派生，不能在订单表单直接改写。
- 金额以整数分计算；拒绝负数、非有限数、超过两位小数和超过支持范围的数值。
- 订单 1,000 元，先收 400、再收 600、退 100 后，收款流水净额为 900 元；报表、订单、AI 与导出一致。
- 退款必须关联本空间、本订单的原收款，累计退款不超过可退余额；订单取消或修改不能抹掉历史收款。
- 不能通过编辑订单金额、删除订单、修改客户关联绕过已发生流水的约束。
- 商品期初库存由期初流水建立；后续变化有原因和流水。入库 10、出库 3 后余 7；禁止负库存和零变动。
- 相同 Idempotency-Key 的相同请求仅记一次；同 key 不同请求被拒绝。过期 revision 返回冲突，前端提示刷新，不覆盖他人修改。
- 业务写入、流水、审计、revision 和去重记录在同一事务中；中途失败不能留下半笔业务。

一期不承诺供应链管理、自动订单扣库存、正式会计报表、税务申报或支付机构代收客户货款。

### S3 · 备份、部署准备与可恢复发布

交付：工作空间导出/空空间恢复、生产配置与迁移、自动化验证、操作手册和恢复方案。

最小验收：

- 业务导出只含当前空间经营数据，不含用户密码、会话、邀请码、服务密钥或其他空间记录。
- 恢复只允许进入空空间；完整检查格式、关联、金额、退款余额、库存流水及汇总；非法文件不产生任何写入。
- 导出后在另一空测试空间恢复，记录数量、金额和库存逐项核对；不覆盖汇报版或其他空间。
- 在独立 PostgreSQL 测试实例实际执行迁移、权限、并发和回滚检查；仅 PGlite 通过不够。
- 生产配置缺少必要 Origin、邀请配置、数据库等条件时明确拒绝启动；HTTPS 会话使用 Secure Cookie。
- 每次发布保留可恢复的版本；数据库迁移有备份、验证和失败处置方法，不能只回滚前端文件。
- 核心浏览器流程、权限隔离、并发写入和备份恢复通过；失败告警与排查手册能定位问题。

本阶段完成表示“具备部署与受邀试用准备”，不等于已在云端运行。

### S4 · 云端受邀试用

交付：独立生产环境、少量受邀经营者、真实流程验证、反馈与故障处理记录。

外部前提：用户持有部署/域名/邮件账户，完成必要验证与付款；确定部署地区、支持渠道和可接受的数据恢复目标。

最小验收：

- 真实 HTTPS 域名下完成登录、保存、退款、库存、导出和跨设备访问；测试与生产数据隔离。
- 有经过验证的账户恢复流程。修改当前密码不等于忘记密码恢复；邮件令牌须有时效、一次性使用及会话失效规则。
- 云数据库自动备份实际启用；在独立环境恢复一次，核对经营数据与账户恢复能力，记录恢复耗时和数据时间点。
- 邀请少量经营者，覆盖服务与商品各一个完整业务流程；问题有记录、负责人及回归结果。
- 具备可用的支持渠道、隐私说明、数据导出/停用政策和故障告知方式，并由用户核对适用的上线要求。
- 任何跨空间访问、丢数据、账款不一致、无法恢复或账户无法恢复的问题，修复并复验前不能扩大发放范围。

### S5 · 收费与商业化验收

交付：单一初始套餐、开通/到期权限、订阅记录、收款与退款流程、服务政策，以及小范围收费验证。

外部前提：用户确认价格、试用期、退款及到期政策、收款主体和渠道，完成商户或服务账户要求。不会因存在支付适配代码就声称已能收款。

可选两条最小收费路径，实施前记录实际选择：

- 人工收款并人工开通：保留可核对的付款依据、开通/续期/撤销审计，明确支持处理时间，不伪装为自动订阅。
- 支付服务商自动开通：服务端校验支付通知，处理重复、延迟、失败和退款；浏览器成功跳转不能独立证明付款成功。

共同验收：

- 订阅权限在服务端执行；前端改套餐字段不能获得付费权限。
- 订阅费用不进入经营者的业务收入；到期按已确认政策限制写入并保留必要的读取/导出能力。
- 收款、开通、退款、到期、重复通知或重复人工操作均能核对与追溯。
- S4 中的安全、数据、备份和账户恢复门槛继续成立；明确服务范围、支持时间、责任人和故障处置入口。

完成 S5 的结论仅适用于已经验证的地区、渠道、业务范围和开放规模，不据此承诺全天候服务或无故障运行。

## 4. 每一步的断点记录

每个可独立恢复的阶段或重要变更完成后，由主流程更新 `COMMERCIAL_PROGRESS.md`，记录：

1. 当前目录、分支、提交与未提交文件；保留协作人员的未完成改动。
2. 已实现内容、尚未实现内容、外部依赖和已决定的业务规则。
3. 实际运行的命令、测试结果与证据路径；区分代码检查、模拟测试、真实服务验证。
4. 服务端口、数据库位置/迁移版本、备份时间点；不得记录真实凭据。
5. 下一步的具体入口和失败时的恢复方法。未通过的阶段不能标记完成。

每个阶段保留对应提交；只推商业分支，不自动合并 main，不强制改写远程历史。发布使用 [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) 逐项留证。
