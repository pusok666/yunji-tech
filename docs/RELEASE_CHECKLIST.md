## B. 身份与工作空间隔离（S1）

- [ ] 注册、邀请校验、登录、退出、会话到期和修改密码可用。
- [ ] 未登录访问业务、备份、审计和 AI 接口返回未授权。
- [ ] 在两个独立空间创建数据，交叉访问客户、订单、商品、收支 ID 被拒绝。
- [ ] 伪造 workspace_id、跨空间关联客户/商品/原收款 ID 不能突破隔离。
- [ ] 导出、恢复、审计、AI 与普通 CRUD 使用相同工作空间限制。
- [ ] 修改浏览器登录标记或 owner 字段不能取得服务端权限。
- [ ] 非允许 Origin、缺失/错误 CSRF 的写请求被拒绝。
- [ ] 密码不明文落库；登录尝试有限制；错误及日志不泄漏账号秘密或其他空间信息。
- [ ] 修改密码后其他旧会话失效；当前会话后续行为符合接口约定。
- [ ] 服务重启、第二浏览器登录后记录一致；不能把浏览器缓存误当持久化证据。

## C. 收款、退款与数据一致性（S2）

- [ ] 新建订单不能指定非零已收款；已收款只从收款减退款得到。
- [ ] 按分计算，拒绝负数、超过两位小数、NaN、Infinity 和超过支持范围的金额。
- [ ] 1,000 元订单收 400、再收 600、退 100，流水净额与订单已收均为 900。
- [ ] 退款关联正确原收款；超额退款、跨订单/跨空间退款被拒绝。
- [ ] 有未退余额不能取消订单；有流水订单不能删除；改金额不能低于已收净额。
- [ ] 修改订单日期不改变既有收款的发生日期；统计按流水日期读取。
- [ ] 订单、收支、Dashboard、AI 和导出的同一范围金额一致。
- [ ] 相同去重 key、相同请求重复执行只记一次；同 key 不同请求返回冲突。
- [ ] 旧 revision 请求返回 409；前端刷新并提示冲突，不静默覆盖。
- [ ] 并行重复收款、退款、改金额请求保持约束，不能出现超收、超退或半笔审计。
- [ ] 模拟事务中途失败，业务、流水、审计、revision 与去重记录共同回滚。
- [ ] 删除/修改手工收支有可追溯审计，不与订单回款重复计算。

## D. 商品与服务基础流程（S2）

- [ ] 服务订单完整走通，不隐式改变商品库存。

- [ ] 入库 10、出库 3 后库存 7，原因、日期和商品关联可追溯。
- [ ] 零变动、负库存、超范围数量、跨空间商品被拒绝。
- [ ] 重复与并行出库保持去重、版本检查和非负库存约束。
- [ ] 有库存流水商品不能删除；低库存/缺货预警与服务端库存一致。
- [ ] 页面明确商品出入库独立操作，未宣称订单自动扣库存。

- [ ] 恢复失败没有任何部分数据；重复恢复请求不重复写入。

## G. 收费门槛（S5）

### 必须完成后才能云端收费

以下两项是收费前的硬性门槛，当前保持未完成；不能以“小规模试用”或“已有幂等接口”替代验证。

- [ ] **平台订阅与经营资金严格隔离。** 平台订阅费、续期和订阅退款使用独立的数据结构、接口与权限，不复用经营者的订单收款/退款入口。实际验证一次订阅收款及退款，确认经营者的订单已收、待回款、现金流报表、AI 汇总与经营备份均不因此变化；保留验证记录。
- [ ] **数据规模与幂等快照增长有明确限制。** 记录并在服务端执行支持的业务记录数、备份体积和请求上限；明确当前“每个幂等 key 保存完整快照”的保留窗口、清理/归档方式与到期重试行为。用接近承诺上限的数据验证导出、恢复、重复请求和数据库增长，证明不会无上限累积完整快照，且清理后不会重复记账。未确定这些限制和证据前，不按长期云端收费服务交付。

### 其他收费验收

- [ ] 用户已确定单一初始套餐、价格、试用期、退款、到期导出和数据保留规则。
- [ ] 收款主体、渠道及所需商户/服务账户已具备；协议由账户持有人处理。
- [ ] 已记录采用“人工收款人工开通”或“支付服务商自动开通”，界面与说明符合实际。
- [ ] 平台订阅记录独立于经营者客户回款，不污染经营收入报表。
- [ ] 付费权限由服务端执行；伪造前端套餐、到期时间或支付成功页面不能开通。
- [ ] 开通、续期、退款、撤销和到期可核对、可追溯；重复操作不重复生效。
- [ ] 若接支付：真实通道配置完成；服务端验证通知；成功、失败、延迟、重复、退款场景均通过。未接支付则注明“不适用”，不得勾选为支付接入已完成。
- [ ] 到期后的读取、写入限制与导出符合用户确认的政策；不能未经说明删除经营数据。
- [ ] S4 的权限、账务、备份、恢复及支持条件仍然成立，并记录本次开放范围。

- “生产验收通过 / 已商业化”——本地构建、单元测试和模拟支付通过不能替代 S4/S5 验收。
