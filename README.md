```bash
npm install
npm run dev
```

也可使用 pnpm，仓库包含 `pnpm-lock.yaml` 和 esbuild 构建授权配置：

```bash
pnpm install --frozen-lockfile

```

构建与预览：

```bash
npm run build
npm run preview
```

开发服务固定端口 `5173`，默认只监听本机。构建文件位于 `dist/`，可用于静态托管。采用 HashRouter，刷新与直接访问 `/#/orders` 均可用。

| 模块 | 能力 |

| 登录 | 演示账号校验、快捷体验、本地登录状态、退出 |

## 建议汇报流程（约 5 分钟）

1. 从登录页进入工作台，介绍服务对象与四项经营指标。
2. 新增一个客户，再为其新增订单：金额 1,000 元、已收 400 元。
3. 到收支管理，展示自动出现的 400 元订单回款；Dashboard 收入同步增加。
4. 把订单已收改为 1,000 元，展示待回款变为 0，收入增加 600 元。
5. 新增库存为 0 的商品，展示预警；修改库存后，预警实时解除。
6. 向 AI 提问“生成今日经营日报”“查询未回款订单”“有哪些库存预警”。
7. 刷新页面，证明本地数据仍保留。演示后可备份或恢复初始数据。

## 数据与计算口径

- 初次打开生成 12 位客户、48 笔订单、8 种商品、30 笔费用。日期以首次生成当天为基准，刷新不会重建。
- `yunji-business-v1` 保存业务数据，`yunji-session` 保存演示登录状态，`yunji-chat` 保存最近 60 条对话。
- 收入 = 订单已收金额 + 手工收入；订单回款由 `ledger()` 动态生成，避免重复入账。
- 修改/删除订单会同步更新/移除关联回款。自动回款不可在收支页直接编辑，应返回订单修改。
- 订单回款按**订单日期**计入，不模拟多次收款的实际发生日期。请勿再次手工录入同一回款。
- 净利润 = 收入 − 支出，为收付实现的演示口径，不是完整会计报表利润。
- 待回款 = 有效订单金额 − 已收金额。已取消订单不参与收入、有效订单数或应收；取消前需将已收清零。
- 库存独立手动维护，本版本订单不自动扣库存；安全库存等于当前库存时即预警。
- 已被订单引用的客户不可直接删除；SKU 不区分大小写且必须唯一。
- 图表、统计与 AI 复用同一计算层。本周为周一至今日，本月为月初至今日，今年为年初至今日。
- 历史区间如“上周”暂不支持，AI 会说明支持范围；未知问法返回可用示例，不编造答案。
- 数据只属于当前浏览器和访问地址，`localhost` 与 `127.0.0.1` 是不同存储空间。请固定使用上述地址。清除浏览器数据会删除记录，建议导出 JSON 备份。
- 读到损坏或不兼容数据时显示警告并禁止写入；备份入口导出原始数据，主动恢复后才替换。保存失败会提示错误，不假报成功。
- 适合单浏览器演示，不支持多标签同时修改时的冲突合并。

## 后续扩展路线

1. **后端与多租户**：Node.js/NestJS 或 FastAPI，PostgreSQL，将 Store 接口替换为 API；加入 workspace_id、审计日志、服务端权限、真实身份认证。
2. **业务闭环**：订单明细、库存流水/预占/冲销、独立收款流水、退款、应收账龄、发票与更完整会计口径。
3. **真实 AI**：实现同源 `POST /api/assistant` 服务端代理；`createApiAssistant()` 已预留请求、超时、异常和结果校验；后端持有 Key，前端不放密钥。
   - 请求：`{ question, context, history }`
   - 响应：`{ answer: string }`
   - 生产环境应由服务端按租户授权查询必要数据，再调用 LLM；写操作需单独确认和审计。
4. **智能经营**：聚合数据查询工具、结构化报表、规则告警，再逐步加入检索增强和有来源的经营建议。
5. **工程化**：后端约束/事务、E2E 持续集成、监控、角色权限、数据迁移、云端备份。

当前应用保留可选 `document.modelContext` 只读经营摘要工具（不支持的浏览器自动跳过），用于后续浏览器 Agent 集成；它与界面共享指标计算。
